Setup Guide

Three things: the Python toolchain, an inference provider that runs the models (Azure Foundry in the cloud, or Ollama on your own machine), and a .env file. Budget about 30–45 minutes the first time.

1. Install the tools

uv (Python and packages)

uv installs the right Python version and every package for the course with one command.

# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
# or on macOS with Homebrew
brew install uv

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Install the course dependencies

cd AiEngineerCourse        # the repository root
uv sync                    # downloads Python 3.12 if needed and installs everything
uv run python --version    # should print Python 3.12.x
Why one root environment? All 40 exercises share the root pyproject.toml, uv.lock and .env. You install once, configure once, and every exercise just works. Always run commands from the repository root.

Optional

  • VS Code with the Python extension. Select the interpreter in .venv/.
  • Node.js, only to use the MCP Inspector in Module 6 (npx @modelcontextprotocol/inspector).

2. Choose an inference provider

The course needs two models: a chat model and, from Lecture 019, an embedding model. An inference provider is whatever runs them and answers your API calls. Pick one; you can switch later by changing one line in .env.

Both speak the same OpenAI-compatible API, so every lecture, exercise and check is the same on both. The code never names a provider: it asks aicourse/settings.py for the base URL, key and model names.

Option A: a model deployment in Azure Foundry

flowchart LR A[Azure subscription] --> B[Foundry resource] B --> C[Chat model deployment
e.g. gpt-4.1-mini] B --> D[Embedding deployment
e.g. text-embedding-3-small] C --> E[Endpoint + API key] D --> E
  1. Sign in at ai.azure.com (Azure AI Foundry) with your Azure account.
  2. Create a project (this also creates a Foundry resource). Pick a region close to you that offers the models below.
  3. Open Models + endpoints → Deploy model → Deploy base model and deploy gpt-4.1-mini. The deployment name you choose is what your code will send as model.
  4. Deploy an embedding model too: text-embedding-3-small (needed from Lecture 019).
  5. Open the chat deployment's page. Copy the endpoint (the base URL, e.g. https://my-resource.openai.azure.com) and a key.
Why gpt-4.1-mini? It supports everything the course uses: tool calling, structured outputs, image input and the temperature parameter, and it's cheap.
Using a newer model instead The course also runs on reasoning models (gpt-5 family, o-series); every exercise is tested on both kinds. Those models only accept the default temperature, so the course detects that once and leaves the parameter out for you. Lecture 004 explains the difference. Whatever you deploy needs tool calling, structured outputs and image input.
Cost The whole course typically costs a few US dollars with a mini model. Set a budget alert in the Azure portal (Cost Management → Budgets) anyway. That's a good habit for any AI project.

Option B: local models with Ollama

  1. Install Ollama from ollama.com and start it. It listens on http://localhost:11434.
  2. Download a chat model and an embedding model (once): 
    ollama pull gemma4:e4b          # chat model, about 10 GB
ollama pull nomic-embed-text    # embedding model, needed from Lecture 019
ollama list                     # the names your code will send as "model"
Using a different local model Any chat model works if ollama show <model> lists the tools and vision capabilities. Set its name in OLLAMA_CHAT_MODEL. Bigger models answer better and slower.
A small model is a different experience A model that fits on a laptop follows instructions less reliably than a large hosted one. A few [live API] checks that grade the model's judgement can fail even when your code is right. Checks run with --offline never depend on the model.

3. Configure .env

cp .env.example .env      # Windows: copy .env.example .env

Open .env, set AICOURSE_PROVIDER, and fill in that provider's block. For Azure Foundry:

AICOURSE_PROVIDER=azure
AZURE_OPENAI_ENDPOINT=https://my-resource.openai.azure.com
AZURE_OPENAI_API_KEY=your-key-here
AZURE_OPENAI_CHAT_DEPLOYMENT=gpt-4.1-mini
AZURE_OPENAI_EMBEDDING_DEPLOYMENT=text-embedding-3-small

For Ollama, one line is enough. The rest have working defaults:

AICOURSE_PROVIDER=ollama
# OLLAMA_BASE_URL=http://localhost:11434
# OLLAMA_CHAT_MODEL=gemma4:e4b
# OLLAMA_EMBEDDING_MODEL=nomic-embed-text:latest

All course code reads these through aicourse/settings.py, which turns the selected block into provider-neutral settings: base_url, api_key, chat_model and embedding_model. The base URL is the provider's OpenAI-compatible v1 API (<endpoint>/openai/v1/ on Azure, http://localhost:11434/v1/ on Ollama), so the standard openai SDK and LangChain's ChatOpenAI work against either unchanged.

Never commit your key .env is listed in .gitignore. If a key ever leaks (pushed to GitHub, pasted in a chat), regenerate it immediately in your provider's portal. A local Ollama has no key to leak, but keep the habit.

4. Verify

uv run python EXER001/solution/check_setup.py   # prints your config with the key masked
uv run python EXER003/solution/raw_call.py      # makes a real call to your chat model

If both work, you're ready for Lecture 001.

Troubleshooting

Azure: 401 Access denied / invalid subscription key

The key doesn't belong to the endpoint's resource, or has a stray space or quote. Copy both values again from the same deployment page.

Azure: 404 DeploymentNotFound

AZURE_OPENAI_CHAT_DEPLOYMENT must be the deployment name, which may differ from the model name. A new deployment can take a minute or two to become available.

Azure: 429 Too Many Requests

Your deployment's tokens-per-minute quota is low. Raise it in the deployment settings, or wait. Lecture 011 teaches retries with backoff.

Azure: connection errors / name resolution failure

Check the endpoint spelling, your network or VPN, and whether the resource uses private networking.

Ollama: connection refused

Ollama is not running. Start the app, or run ollama serve. If it listens somewhere else, set OLLAMA_BASE_URL.

Ollama: 404 model not found

The model is not downloaded, or the name differs from what ollama list shows (the tag after the colon counts). Run ollama pull <model>.

Ollama: the first answer is slow, or a request times out

The first call loads the model into memory, which can take a minute. Later calls are fast while it stays loaded. Raise AICOURSE_REQUEST_TIMEOUT on a slow machine.

Ollama: long conversations or documents get cut off

Ollama's context window is set on the server, not per request. Check it with ollama ps and raise it with the OLLAMA_CONTEXT_LENGTH environment variable before starting Ollama.

"Course configuration problem: … is missing"

The .env file is missing, in the wrong folder (it must be at the repository root), or a variable name is misspelled.
