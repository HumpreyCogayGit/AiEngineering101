Glossary

The vocabulary of AI engineering, in plain words. The number in brackets is the lecture that covers it.

Agent
A loop in which a model decides on actions (tool calls), observes the results and decides again until the task is done. [017, 027]
Agentic RAG
RAG where the system decides whether to retrieve, grades what it retrieved, and can rewrite the query and retry. [030]
API key
A secret string that authenticates your requests. Treat it like a password. [001]
Backoff (exponential)
Waiting longer after each failed attempt (1 s, 2 s, 4 s …) before retrying, usually with random jitter. [011]
BM25
A classic keyword-ranking algorithm. Good at exact terms, names and codes, which vector search can miss. [023]
Callback
A function LangChain calls on events (model start/end, tool start/end/error). It's the basis of tracing. [035]
Checkpointer
LangGraph component that saves graph state after every step, keyed by thread_id. It provides conversation memory and pause/resume. [028]
Chunk / chunking
Splitting documents into smaller passages before embedding them. Chunk size and overlap are key RAG settings. [020]
Command (LangGraph)
A value a node returns to update the state and name the next node in one step. It is how one agent hands control to another. [031]
Completion
The model's generated output for a request. "Chat completion" is the message the model returns. [003]
Container image
A packaged, runnable copy of an application with its dependencies. Built from a Dockerfile; anything copied into it is published with it, so it must hold no secrets. [040]
Content block
One typed part of a message's content (text, image …). Lets a single message mix modalities. [006]
Content filter
A hosted provider's safety system (Azure has one) that can block harmful prompts or outputs, returned as an HTTP 400 with code content_filter. A local model has none. [036]
Context window
The maximum number of tokens (input + output) a model can handle in one request. [006]
Conversation summary
A model-written condensation of old turns that replaces them in the context. Keeps the gist, can lose or distort a detail. [006, 039]
Cosine similarity
A measure of how closely two vectors point in the same direction (1 = same, 0 = unrelated). [019]
Deployment (Azure)
A named instance of a model in your Azure resource. On Azure, the request's model field is the deployment name. [001]
Embedding
A vector of numbers representing the meaning of a text. Similar meanings give nearby vectors. [019]
Faithfulness
Whether every claim in an answer is supported by the retrieved context. The opposite is hallucination. [024]
Few-shot prompting
Including worked examples (input → output) in the prompt to show the model the task. [008]
Finish reason
Why generation stopped: stop (natural end), length (token limit), tool_calls, content_filter. [004]
Grounding
Restricting the model to answer from provided sources, ideally with citations. [022]
Hallucination
Fluent output that is false or unsupported. [022, 024]
Handoff
One agent passing control directly to another, without a supervisor deciding in between. Fewer model calls; routing logic is spread across the agents. [031]
Hit rate
The share of test questions for which retrieval returns the expected document in the top k. [023]
Human in the loop (HITL)
Pausing an agent so a person can approve, edit or reject an action before it happens. [029]
Idempotent
Safe to run twice: running again does not change the result (e.g. re-ingesting without duplicates). [021]
Inference provider
The service that runs a model and answers API calls: in this course Azure Foundry (cloud) or Ollama (local). Selected with AICOURSE_PROVIDER; the code stays the same. [001]
Interrupt
LangGraph's interrupt(): pause a graph mid-node and resume later with Command(resume=…). [029]
JSON mode
A setting that guarantees the reply is valid JSON, though not that it matches your schema. [009]
JSON Schema
A standard way to describe the shape of JSON data. Used for tool parameters and structured outputs. [009, 016]
LCEL
LangChain Expression Language: composing runnables with the pipe operator |. [013]
Least privilege
Giving an agent only the tools and permissions its task needs. [034, 036]
Liveness check
An endpoint that answers "is the process able to respond at all?". The platform restarts a container that fails it, so it must depend on nothing else. [040]
LLM-as-judge
Using a model with a scoring rubric to grade outputs that simple string matching can't evaluate. [024]
MCP (Model Context Protocol)
An open standard connecting AI applications (hosts/clients) to servers that expose tools, resources and prompts. [032]
MMR (Maximal Marginal Relevance)
A retrieval method that balances relevance with diversity, avoiding near-duplicate results. [023]
MRR (Mean Reciprocal Rank)
The average of 1/rank of the first correct result. Rewards putting the right document first. [024]
Multimodal
Handling more than one type of input, e.g. text and images. [006]
Ollama
A program that runs open models on your own machine and serves them through an OpenAI-compatible API at http://localhost:11434/v1/. [001]
OpenAI-compatible API
The HTTP API shape (/v1/chat/completions, /v1/embeddings) that many providers implement, so one client library works with all of them. [003]
Parallel tool calls
Several tool requests in a single model reply. Each one needs its own tool result, matched by id, before the model is called again. [016, 017]
Prompt injection
Instructions hidden in untrusted text (emails, web pages, tool results) that try to override yours. [036]
RAG (Retrieval-Augmented Generation)
Retrieving relevant passages and putting them in the prompt so the model answers from your data. [022]
Rate limit
A cap on requests or tokens per minute. Exceeding it returns HTTP 429. [011]
ReAct
The "reason + act" agent pattern: think, call a tool, observe, repeat. [027]
Readiness check
An endpoint that answers "can this instance serve a request right now?". The platform sends no traffic while it fails. [040]
Reasoning model
A model family (gpt-5, o-series) that thinks before answering. It only accepts the default temperature and is steered by the prompt and a reasoning-effort setting. [004]
Reducer
In LangGraph, a function that defines how a state key is updated, e.g. append instead of replace. [026]
Reranking
Reordering retrieved candidates with a stronger (slower) relevance model. [023]
Responses API
OpenAI's newer API, which LangChain uses for recent models. Answers arrive as a list of content blocks, so read them with .text. [012]
RRF (Reciprocal Rank Fusion)
Merging several ranked lists by summing 1/(k + rank) for each document. [023]
Runnable
LangChain's universal interface with invoke, stream and batch. Models, prompts, parsers and chains are all runnables. [012]
Session state
Streamlit's per-browser-session storage that survives script re-runs. [015]
SSE (Server-Sent Events)
The HTTP streaming format the API uses to send tokens as they are generated. [007]
Stateless
The model remembers nothing between requests. Your code must resend the conversation. [005]
stdio transport
Running an MCP server as a subprocess and talking JSON-RPC over its stdin/stdout. [032]
Store (LangGraph)
Long-term key-value memory organized by namespace (e.g. per user), shared across threads. [028]
Structured output
Constraining the model's reply to a JSON schema (often from a Pydantic model). [009, 014]
Supervisor
A multi-agent pattern where a coordinator agent routes work to specialist agents. [031]
System prompt
The instruction message that sets the assistant's role, rules and style. [005]
Temperature
A sampling setting. Low values give focused, repeatable output; high values give more variety. [004]
Thread
One conversation, identified by thread_id in LangGraph. [028]
Time to first token (TTFT)
Latency until the first piece of a streamed answer arrives. [007]
Token
A chunk of text (about ¾ of an English word) that models read and write. Pricing and limits are in tokens. [004]
Tool calling
The model requests a function call with JSON arguments; your code runs it and returns the result. [016]
Trace / span
A record of one run (trace) made of timed steps (spans), such as model calls and tool calls. [035]
Trajectory
The ordered list of tool calls an agent made during one run. Scored for the right tools, order and arguments, beside the final answer. [038]
Vector store
A database that stores embeddings and finds the nearest ones to a query vector. [021]
