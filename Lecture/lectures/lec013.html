Prompts and Chains

Prompt templates, models and output parsers all share one interface, so the pipe operator | can join them into a chain that is itself a runnable.

Overview

Real features are rarely one call. "Summarize, then translate" or "extract, then classify" are pipelines. LangChain Expression Language (LCEL) lets you declare such pipelines from small, testable pieces, and you get stream, batch and async on the whole pipeline for free.

Concept

Prompt templates

summary_prompt = ChatPromptTemplate.from_messages([
    ("system", "You summarize news articles accurately and neutrally."),
    ("human", "Summarize the following article in at most {max_words} words:\n\n{text}"),
])
summary_prompt.input_variables          # ['max_words', 'text']
summary_prompt.invoke({"text": "...", "max_words": 40})   # -> filled-in messages

Templates separate the fixed part of a prompt from the variables, so the prompt can be reviewed, versioned and tested on its own.

The pipe

chain = summary_prompt | llm | StrOutputParser()
chain.invoke({"text": article, "max_words": 40})     # -> "The council approved ..."
flowchart LR I["{text, max_words}"] --> P[ChatPromptTemplate] -->|messages| M[Chat model] -->|AIMessage| O[StrOutputParser] --> S["str"]

Each step's output is the next step's input. StrOutputParser turns an AIMessage into a plain string.

Passing data along: RunnablePassthrough.assign

Step 2 often needs both the original input and step 1's output. assign keeps the input dict and adds a new key:

pipeline = (
    RunnablePassthrough.assign(summary=summary_chain)          # adds "summary"
    | RunnablePassthrough.assign(translation=translate_chain)  # uses "summary", adds "translation"
)
pipeline.invoke({"text": article, "max_words": 40, "language": "Filipino"})
# {"text": ..., "max_words": 40, "language": "Filipino", "summary": "...", "translation": "..."}
flowchart LR A["{text, max_words, language}"] --> B["assign(summary=...)"] --> C["{..., summary}"] --> D["assign(translation=...)"] --> E["{..., summary, translation}"]

Other building blocks you'll meet

Goal

  1. Write ChatPromptTemplates with variables.
  2. Compose prompt, model and parser with |.
  3. Chain steps where later steps use earlier outputs, using RunnablePassthrough.assign.
  4. Use batch on a chain.

Success Criteria

  • The script shows the template variables, a summary, a translation and a 3-language batch
  • The pipeline output contains the original inputs plus summary and translation
  • All 5 checks pass

Walkthrough

  1. Write both templates first and print .input_variables to confirm them.
  2. Each chain is one line with |.
  3. For the pipeline, pipe two assign calls. The check confirms the translation step received the summary.

Common Pitfalls

Literal braces in templates

{ starts a variable. To show JSON examples in a template, double the braces: {{"key": "value"}}.

Key mismatches

The translate template expects {summary}; if the previous step produces "summ", you get a missing-variable error. Name keys consistently.

Long chains are hard to debug

Test each piece alone first. Tracing (Lecture 035) shows each step's input and output.

Discussion

Is one big prompt ("summarize and translate") better than two steps?

One call is cheaper and faster. Two steps are easier to test, cache and reuse, and each prompt does one job well. For complex tasks, decomposition usually wins on quality.

When do chains stop being enough?

When the flow needs loops or decisions at runtime: retry, branch, call tools until done. That's what LangGraph is for (Module 5).
