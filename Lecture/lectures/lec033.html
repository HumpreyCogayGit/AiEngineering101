Build Your Own MCP Server

With FastMCP, a decorated Python function becomes a tool that any MCP host can discover and call.

Overview

You'll build a notes server: create, list, search and delete notes; read a note as a resource; and offer a prompt that summarizes them. The check script then acts as an MCP host: it starts your server as a subprocess and tests it through the protocol, exactly as a desktop app or agent would.

Concept

FastMCP

from mcp.server.fastmcp import FastMCP
mcp = FastMCP("notes")

@mcp.tool()
def search_notes(query: str) -> list[dict]:
    """Find notes whose title or content contains the query (case-insensitive)."""
    ...

@mcp.resource("notes://{note_id}")          # a resource TEMPLATE: {note_id} becomes an argument
def read_note(note_id: str) -> str: ...

@mcp.prompt()
def summarize_notes(tag: str = "") -> str: ...

if __name__ == "__main__":
    mcp.run()                                # stdio by default

As with LangChain's @tool, type hints become the JSON schema and the docstring becomes the description. The protocol plumbing (handshake, discovery, serialization, errors) is handled for you.

Designing tools for models

PrincipleIn the notes server
Clear names and descriptionssearch_notes: "Find notes whose title or content contains…"
Small, typed argumentstag: str | None = None
Compact resultsList and search return id, title and tags, not full content; read a note via the resource
Errors the model can act on"No note with id abc. Use list_notes to see valid ids."
Destructive operations separatedelete_note is its own tool, so hosts can block it (Lecture 034)

Errors

Raise an exception (e.g. ValueError) in a tool, and FastMCP returns a result with isError: true and your message. The host and model see it as a normal tool result, and the server keeps running.

Configuration and state

The server reads its storage path from the NOTES_FILE environment variable, which hosts set when they launch it. That's how the checks give every test a fresh, empty notes file.

Connecting it to other hosts

Most MCP hosts are configured with a small JSON block naming the command to start your server, for example:

{
  "mcpServers": {
    "notes": {
      "command": "uv",
      "args": ["run", "--project", "/path/to/AiEngineerCourse", "python", "EXER033/solution/notes_server.py"],
      "env": {"NOTES_FILE": "/path/to/my-notes.json"}
    }
  }
}

Goal

  1. Create an MCP server with FastMCP tools, resource templates and prompts.
  2. Design tool interfaces and error messages that models use well.
  3. Configure a server through environment variables.
  4. Test a server through the protocol.

Success Criteria

  • All four tools work, and errors come back as error results, not crashes
  • notes://<id> returns the note text
  • summarize_notes builds a prompt that contains the notes
  • All 6 checks pass

Walkthrough

  1. Follow the pattern of add_note for the other tools.
  2. Use load() and save() for storage, and summary() for compact results.
  3. Run the checks after each capability. The first check stays "TODO" until all three tools exist.
  4. Bonus: register the server in an MCP host you use and let it keep notes for you.

Stretch goals

Optional, for when the checks pass. Neither goal is needed for "complete", and the checks must still pass afterwards.

  1. Extend. Add an update_note tool with partial updates: only the fields that are passed change. Done when: updating the content leaves title and tags alone, and a call with no fields returns an error result.
  2. Connect (EXER032). Add a resource that lists all notes, and read it from a client. Done when: notes://index returns id, title and tags of every note, and notes://<id> still returns one note.

Reference code, for after you have tried: EXER033/stretch/

Common Pitfalls

Docstrings written for humans only

The model reads them to decide when to call. Say what the tool does, when to use it, and what it returns.

Returning everything

A list_notes that returns full contents of 500 notes floods the context. Return summaries.

Concurrent writes

A JSON file is fine for one user. Several clients writing at once need a database.

Discussion

Tool, resource or prompt?

If the model should decide when to fetch it, make it a tool. If the app or user picks what to load into context, make it a resource. If it's a reusable task the user triggers, make it a prompt.

How would you make this server multi-user and remote?

Streamable HTTP transport, authentication (OAuth is part of the MCP spec), and per-user storage keyed by the authenticated identity.
