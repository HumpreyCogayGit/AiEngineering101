Chat With Your Docs

Turn the RAG pipeline into a product: upload files, ask follow-up questions, and see the sources behind every answer.

Overview

This is Module 4's integration project. It combines loading (020), indexing (021), grounded answering (022) and Streamlit (015) into one app, and adds the one new piece a conversation needs: question condensing, so that follow-ups like "How much is it?" can be searched.

Concept

Why follow-up questions break naive RAG

User: Tell me about the cold brew bottle.
Bot:  It's a 1 litre glass bottle with a fine mesh filter [1].
User: How much is it?        ← search for "How much is it?" finds... anything with a price

The retriever only sees the last message. The fix is to rewrite it into a standalone question using the history before searching: "How much does the Nimbus Cold Brew Bottle cost?"

flowchart LR H[Chat history] --> C[Condense with LLM] Q[Follow-up question] --> C C --> S[Standalone question] --> R[Retrieve] --> G[Grounded answer] --> U[Answer + sources]

Skip the condensing call when there's no history. It's an extra LLM call, so don't pay for it on the first question.

Per-session indexes

Uploaded documents belong to one user's session. We build an in-memory Chroma collection (EphemeralClient) with a unique name per session, stored in st.session_state. Users never see each other's files, and nothing is left on disk.

Handling uploads safely

  • Restrict file types (type=["md", "txt", "html", "pdf"]).
  • Use only the base name of the uploaded filename (Path(name).name); never trust a path from the client.
  • Process in a temporary directory that's cleaned up automatically.
  • Think about limits: file size, number of files, scanned PDFs without text.

Showing sources

An expander under each answer shows the passages used, with file names and PDF page numbers. Users can verify answers, which builds justified trust, and you can debug retrieval at a glance.

Worked example: a follow-up question, with and without condensing

Two turns against the sample documents. Chunks are written as file#chunk_id; the Cold Brew Bottle is in products.md#14.

Turn 1. "Tell me about the cold brew bottle." The history is empty, so condense_question returns the question unchanged, without a model call.

searched for  Tell me about the cold brew bottle.
retrieved     products.md#14, brewing_guide.md#1, brewing_guide.md#0, products.md#13
answer        The **Cold Brew Bottle** is a 1-litre glass bottle with a fine mesh filter, priced at **₱980**. [1]

Turn 2. "How much is it?" First, what a search for those four words finds:

searched for  How much is it?
retrieved     products.md#14, company_faq.md#6, shipping.md#18, loyalty_program.md#9

Three of the four chunks are whatever mentions a price: the ₱20 cup discount, the shipping fees, the loyalty stars. The catalog chunk is first here only because this knowledge base is tiny and that chunk is full of prices. With a thousand documents, "How much is it?" matches every price list you own.

Now with condensing. The model receives the last turns and the follow-up, and writes:

standalone    How much does the 1-litre Cold Brew Bottle cost?
retrieved     products.md#14, brewing_guide.md#1, company_faq.md#6, products.md#13
answer        The 1-litre Cold Brew Bottle costs ₱980. [1]

Compare the two retrieved lists. The shipping and loyalty chunks are gone; the cold brew section of the brewing guide and a second catalog chunk took their places. The search is now about a product, not about prices in general.

Three things to take from this run:

  • The rewrite pulled a fact from the history. "1-litre" was in the bot's previous answer, not in anything the user typed. That is useful here, and it is also how condensing drifts: the model can just as easily carry over something wrong. The Sources expander shows the standalone question so you can see it.
  • The answer step never saw the history. It received the standalone question and four chunks. Everything it needed was in the rewritten question.
  • Turn 2 cost two model calls, turn 1 cost one. Condensing is paid on every follow-up, which is why the first question skips it.

Captured from a real run. Your ids, wording and numbers will differ; the shape will not.

The Project

A Streamlit app: a sidebar uploader (plus a "use sample documents" option), a "Build index" button, a chat with conversational RAG, and a Sources expander showing the standalone query that was searched.

uv run streamlit run EXER025/starter/app.py

Goal

  1. Build conversational RAG with question condensing.
  2. Index user uploads in a per-session, in-memory vector store.
  3. Handle uploaded files safely.
  4. Present sources so users can verify answers.

Success Criteria

  • Uploading a PDF or Markdown file and clicking "Build index" works
  • Follow-ups work: "Tell me about the cold brew bottle" → "How much is it?"
  • Every answer has a Sources expander with file names (and PDF page numbers)
  • Two browser tabs do not see each other's documents
  • All 7 checks pass

Walkthrough

  1. Complete docs_logic.py and pass its checks before touching the UI.
  2. condense_question must make no LLM call when the history is empty; the check verifies this.
  3. In app.py, build the index inside st.spinner, since embedding takes a few seconds.
  4. Upload one of your own documents and ask about it.

Stretch goals

Optional, for when the checks pass. Neither goal is needed for "complete", and the checks must still pass afterwards.

  1. Extend. Let the user remove one uploaded file from the index. Done when: after Remove, the file is gone from the list and no answer cites it; the other files are not re-embedded.
  2. Connect (EXER024). Add thumbs up/down under each answer and write the feedback to a file. Done when: each rating adds one line to stretch/output/feedback.jsonl with the question, the sources and the answer.

Reference code, for after you have tried: EXER025/stretch/

Common Pitfalls

Rebuilding the index on every rerun

Streamlit reruns on every message. Keep the store in st.session_state and rebuild only when the button is clicked.

A shared global collection

One collection for all users leaks one user's documents into another's answers. That's a privacy incident.

Condensing drifts the question

The rewrite can change the meaning. Show the standalone query in the Sources expander so you can spot it.

Discussion

What changes for 10,000 documents instead of 3 uploads?

Ingestion becomes an offline job, the index is persistent and shared (with per-document access control in metadata filters), and you'd consider a managed store like Azure AI Search.

Should the answer step see the chat history too?

Sometimes. It helps with tone and references ("as I said…"), but grounding works best when the answer comes from retrieved context. Here, the history only shapes the search.
