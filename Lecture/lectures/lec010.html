Building a CLI App

The terminal is where developers live. A good command-line tool composes with everything else: pipes, scripts, cron jobs and CI.

Overview

You'll package Module 1 into a real tool, ask.py, with sub-commands, options, help text, streaming output, stdin piping and proper exit codes. We use Typer, which builds the CLI from Python type hints.

Concept

Anatomy of a CLI

ask.py  summarize   notes.txt   --words 50
        └ command   └ argument  └ option (with a value)
app = typer.Typer(help="Ask an LLM from your terminal.")

@app.command()
def ask(
    question: Annotated[str, typer.Argument(help="The question to ask")],
    temperature: Annotated[float, typer.Option("--temperature", "-t", min=0.0, max=2.0)] = 0.7,
) -> None:
    """Ask a single question."""            # becomes the help text
    ...

if __name__ == "__main__":
    app()

Typer reads the type hints to parse and validate input (-t abc is rejected) and generates --help from docstrings and help= texts.

Testable by design

The tool gets its client through a small get_client() function. Tests replace that one function with a fake, and Typer's CliRunner invokes commands in-process and captures output and exit codes. This is dependency injection in its simplest form.

Goal

  1. Build a multi-command CLI with arguments, options and help text.
  2. Support stdin piping, and separate stdout from stderr.
  3. Return meaningful exit codes.
  4. Test a CLI offline by injecting a fake client.

Success Criteria

  • --help shows all three commands with descriptions
  • Answers stream to the terminal
  • Piping text into summarize - works
  • A missing file prints an error to stderr and exits with code 1
  • All 6 checks pass

Walkthrough

  1. stream_answer is your EXER007 code, with typer.echo(piece, nl=False) instead of print.
  2. Implement read_input, then register summarize with @app.command(). Until you do, it's missing from --help.
  3. raise typer.Exit(1) ends the program with exit code 1.
  4. Try it for real: uv run python EXER010/starter/ask.py summarize README.md --words 30.

Stretch goals

Optional, for when the checks pass. Neither goal is needed for "complete", and the checks must still pass afterwards.

  1. Extend. Add a --json flag to ask that prints one machine-readable object instead of streaming text. Done when: the output pipes cleanly into python -m json.tool.
  2. Connect (EXER008). Add a classify command that reuses the EXER008 prompt. Done when: the command prints one label and nothing else, for an argument and for piped input.

Common Pitfalls

Printing errors to stdout

Then ask.py summarize x > summary.txt writes the error message into the file. Errors go to stderr.

Using sys.exit() deep inside library code

Only the CLI layer should decide to exit. Library functions should raise exceptions; the command turns them into exit codes.

Huge files

Summarizing a 500-page file overflows the context window. A real tool would chunk it (Lecture 020) and summarize in stages.

Discussion

Why build a CLI when a web UI is friendlier?

Automation. A CLI can run in CI to review pull requests, in cron to summarize logs, or in a shell pipeline. Many production AI features start as internal CLI tools.

What would you add next?

A --json output flag for scripts, a config file for defaults, and caching of identical requests.
