Streaming

A 20-second answer feels slow; the same answer appearing word by word after 0.5 seconds feels fast. Streaming doesn't make the model faster, but users experience it as much faster.

Overview

Models generate one token at a time. Without streaming, the server waits until the last token, then sends everything at once. With stream=True it sends each piece as soon as it exists. This lecture covers the wire format, how to consume it in Python with generators, and how to get usage data from a stream.

Concept

Server-Sent Events (SSE)

The HTTP response stays open and the server writes lines like these:

data: {"choices":[{"delta":{"role":"assistant","content":""}}]}
data: {"choices":[{"delta":{"content":"Rivers"}}]}
data: {"choices":[{"delta":{"content":" wind"}}]}
data: {"choices":[{"delta":{"content":" through"}}]}
data: {"choices":[{"delta":{},"finish_reason":"stop"}]}
data: {"choices":[],"usage":{"prompt_tokens":14,"completion_tokens":152,...}}   ← only with include_usage
data: [DONE]

Each chunk carries a delta, the new piece only. You assemble the full text by concatenating deltas.

Consuming a stream with a generator

def stream_reply(client, messages):
    stream = client.chat.completions.create(model=..., messages=messages, stream=True)
    for chunk in stream:
        if not chunk.choices:          # usage chunk, or Azure's content-filter chunk
            continue
        delta = chunk.choices[0].delta.content
        if delta:                      # role-only and final chunks have no content
            yield delta

for piece in stream_reply(client, messages):
    print(piece, end="", flush=True)   # flush: show it NOW, don't buffer

A function with yield is a generator. It produces values lazily, one at a time, which is a natural fit for streams. The same generator can feed a terminal, a web UI (Lecture 015) or an API endpoint.

Latency: TTFT vs total time

time →         0s        1s        2s   ...   7s        8s
Non-streaming  [ waiting, nothing on screen .................. ] full answer appears
Streaming      [.] first token (TTFT ≈ 0.5s)
                  Rivers wind through ancient valleys, carving ... ...  done

Time to first token (TTFT) is what users feel. Total time is roughly the same either way.

The Project

A streaming chatbot for the terminal, plus stream_with_usage() (token counts from a stream) and a measurement that prints time-to-first-token against total time.

Goal

  1. Explain SSE, chunks and deltas.
  2. Write a generator that yields text deltas and handles chunks without content.
  3. Get token usage from a stream with stream_options={"include_usage": True}.
  4. Measure TTFT and explain why streaming improves perceived latency.

Success Criteria

  • Answers appear progressively in the terminal, not all at once
  • On exit the script prints time-to-first-token and total time; the first is much smaller
  • Chunks without choices (the usage chunk, or Azure's content-filter chunk) don't crash your code
  • All 5 checks pass

Walkthrough

  1. Write stream_reply as above; the check verifies it's a real generator.
  2. collect is the "consumer" side: call on_token for each piece and join everything at the end.
  3. For stream_with_usage, remember the usage arrives in a final chunk whose choices list is empty.

Common Pitfalls

IndexError on chunk.choices[0]

Azure may send a first chunk with prompt filter results and no choices, and the usage chunk also has none. Always check.

Text appears all at once anyway

The terminal buffers output. Use print(..., end="", flush=True).

Forgetting to store the streamed reply in history

Collect the pieces and append the full text as the assistant message, or your bot forgets what it just said.

Content filtering mid-stream

Azure screens output as it's generated. A stream can stop with finish_reason="content_filter" after some text has already been shown. Handle that case in the UI.

Discussion

When should you not stream?

When code consumes the output: JSON for a parser, a classification label, a tool call. You need the complete answer before you can use it, so streaming only adds complexity.

How does streaming interact with guardrails?

Output checks need the whole text, but you've already shown part of it. Options: check chunks incrementally, buffer a sentence before showing it, or accept the risk for low-stakes content.
