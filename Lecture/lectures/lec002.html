Python Primer for AI Engineers

LLM APIs speak JSON. In Python, JSON becomes dicts and lists. This lecture covers the small slice of Python you'll use in every later exercise.

Overview

You don't need to be a Python expert to build AI applications, but you do need to read and build nested data fluently, write small functions, handle errors, and validate data. That is the scope of this primer. Everything here runs offline: no API key needed.

A chat API response is a dict containing a list of dicts containing a dict. To get the text you chain lookups:

response["choices"][0]["message"]["content"]
#        dict key   list  dict key   dict key

Functions with type hints

def build_request(model: str, user_text: str, system_text: str | None = None) -> dict:
    messages: list[dict] = []
    if system_text:                      # None and "" are both "falsy"
        messages.append({"role": "system", "content": system_text})
    messages.append({"role": "user", "content": user_text})
    return {"model": model, "messages": messages}

Type hints (str, str | None, -> dict) aren't enforced at runtime, but they document intent and let your editor catch mistakes. Frameworks also read them: LangChain builds tool schemas from them (Lecture 017) and FastMCP builds MCP schemas from them (Lecture 033).

Exceptions

Real data is messy. A response might have no choices, or a message might be None. Instead of crashing, catch the specific errors you expect:

try:
    return response["choices"][0]["message"]["content"]
except (KeyError, IndexError, TypeError):   # missing key, empty list, None["..."]
    return None
Never use a bare except: It also catches typos in your own code and Ctrl+C. Name the exceptions you expect.

Pydantic: validated data

A Pydantic model is a class that checks its data when created. This is the backbone of structured outputs (Lecture 009), tool arguments and settings.

from typing import Literal
from pydantic import BaseModel

class Message(BaseModel):
    role: Literal["system", "user", "assistant"]
    content: str

Message(role="user", content="hi")        # ok
Message(role="robot", content="beep")     # raises ValidationError
Message(**{"role": "user", "content": "x"})  # ** unpacks a dict into keyword arguments

Common Pitfalls

Mixing up json.load and json.loads

load reads from a file object; loads (load string) parses a string. Same for dump/dumps.

Mutating shared data by accident

Lists and dicts are passed by reference. If a function appends to a list it received, the caller's list changes too. You'll see why Conversation.to_api() returns a copy in Lecture 005.

Catching too much

except Exception around a big block hides bugs. Keep try blocks small and the exception list specific.

Discussion

When should a function return None, and when should it raise?

Return None when "no value" is a normal outcome the caller should handle. Raise when it signals a real problem the caller probably can't continue past. safe_get_reply is for situations where a missing reply is expected.

Why does AI engineering lean so heavily on Pydantic?

Models produce text, and programs need typed data. Pydantic is the bridge: describe the shape once, and get validation, error messages and a JSON Schema the model can be constrained to.
