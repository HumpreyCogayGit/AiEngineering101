LangChain Chat Models

You've built everything by hand. Now meet the framework, and see exactly which of your code it replaces.

Overview

LangChain is a library of standard interfaces and integrations for LLM applications. Its central abstraction is the chat model: one interface (invoke, stream, batch) whether the model is on Azure, OpenAI, Anthropic, or running locally. Everything else in Modules 2–7 builds on it.

Concept

Why a framework?

  • Provider independence: switching models is a one-line change.
  • Typed messages: SystemMessage, HumanMessage, AIMessage, ToolMessage instead of dicts.
  • Composability: models, prompts and parsers plug together (Lecture 013).
  • Ecosystem: tools, retrievers, vector stores, LangGraph agents and tracing all speak the same interface.

The cost is an extra layer to learn and debug. That's why you built the raw version first.

r = client.chat.completions.create(

r.choices[0].message.content

LangChain

llm = ChatOpenAI(model=dep, base_url=..., api_key=...)
reply = llm.invoke([
    SystemMessage("Be brief"),
    HumanMessage("Hi"),
])
reply.text             # the answer as a string
reply.usage_metadata   # tokens, standardized
Why ChatOpenAI and not AzureChatOpenAI? AzureChatOpenAI targets Azure's older, versioned API (api_version=…). With the OpenAI-compatible v1 endpoint, the standard ChatOpenAI with a base_url is simpler and recommended. Both work. The same reasoning covers Ollama: LangChain has a native ChatOllama, but Ollama's OpenAI-compatible endpoint lets one ChatOpenAI serve every provider in this course, so switching provider changes only .env.

.text or .content?

An AIMessage has both, and they are not the same thing:

AttributeWhat you getUse it for
reply.textAlways a string: the text of the answerPrinting, parsing, comparing, storing the answer
reply.contentA string or a list of content blocks, depending on the modelPassing a message on unchanged; reading non-text blocks
reply = llm.invoke("Say hi")
reply.content   # classic model:   'Hi'
                # reasoning model: [{'type': 'text', 'text': 'Hi', 'annotations': [], 'id': 'msg_...'}]
reply.text      # 'Hi' on both

The reason is underneath LangChain. For newer OpenAI models (the gpt-5 family) ChatOpenAI talks to the Responses API instead of the Chat Completions API you used in Module 1, and that API returns answers as blocks. The same is true for streamed chunks. Code that does reply.content.lower() works on one model and raises AttributeError: 'list' object has no attribute 'lower' on the next. Read answers with .text everywhere and your code survives a model change.

Common Pitfalls

Outdated tutorials

LangChain changed a lot between versions. Old imports (from langchain.chat_models import …) and classes (LLMChain, ConversationChain) are legacy. This course uses LangChain 1.x with langchain_core and langchain_openai.

content isn't always a string

On reasoning, multimodal and tool-using models, AIMessage.content is a list of blocks, so string methods fail on it. Use .text whenever you need the answer as a string, including on streamed chunks.

Discussion

When would you not use LangChain?

A single, simple call in a small script, or when you need provider features the abstraction doesn't expose yet. The raw SDK is always an option, and you know how to use it.

What does provider independence really buy you?

The ability to evaluate a cheaper or better model by changing one line, and to fall back to another provider during an outage.
