MCP Concepts and Using a Server

The Model Context Protocol is a standard plug between AI applications and tools. Write a tool server once, and any MCP-aware app can use it.

Overview

So far your tools lived inside your Python program. Every app that wants a "notes" or "database" tool would have to re-implement it. MCP standardizes how applications discover and call tools, read data and fetch prompt templates from external servers. Claude Desktop, VS Code, many agent frameworks, and your LangChain agents can all use the same MCP server.

Concept

Hosts, clients, servers

flowchart LR subgraph Host["Host application (your agent, an IDE, a desktop app)"] C1[MCP client] C2[MCP client] end C1 <-->|"JSON-RPC over stdio"| S1["MCP server: coffee
(local subprocess)"] C2 <-->|"JSON-RPC over HTTP"| S2["MCP server: remote service"]
RoleIs
HostThe app the user interacts with; it contains the LLM and decides what to call
ClientOne connection to one server, inside the host
ServerA program exposing capabilities; it knows nothing about the LLM

Three capability types

CapabilityControlled byExample
ToolsThe model (it decides to call them)get_product(name)
ResourcesThe application (it decides what to load)menu://today
PromptsThe user (picks a template, e.g. a slash command)barista_recommendation(taste)

Transports

  • stdio: the host starts the server as a subprocess and talks over stdin/stdout. Local, simple, no network. (That's why a stdio server must never print().)
  • Streamable HTTP: the server runs as a web service, possibly remote and shared, with authentication.

A session

async with stdio_client(StdioServerParameters(command=sys.executable, args=["coffee_server.py"])) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()                       # handshake: versions + capabilities
        tools = await session.list_tools()               # discovery: names, descriptions, JSON schemas
        result = await session.call_tool("get_product", {"name": "Barako Bold"})
        menu = await session.read_resource("menu://today")

MCP tools in LangChain

client = MultiServerMCPClient({"coffee": {"command": sys.executable, "args": [SERVER], "transport": "stdio"}})
tools = await client.get_tools()             # regular LangChain tools
agent = create_agent(llm, tools)
await agent.ainvoke({"messages": [...]})     # MCP tools are async: use ainvoke

Goal

  3. Load MCP tools into a LangChain agent.

Success Criteria

  • The script lists the server's tools, resources and prompts
  • A bad product name returns a readable error, not a crash
  • The agent answers a multi-part question by calling several MCP tools
  • All 7 checks pass

Walkthrough

  1. Read coffee_server.py first. Notice how little code a server needs.
  2. Implement the raw client functions; each one opens its own session, which is fine for learning.
  3. Optional: with Node.js installed, run the MCP Inspector and click through the server: npx @modelcontextprotocol/inspector uv run python EXER032/servers/coffee_server.py

Common Pitfalls

Printing to stdout in a stdio server

Your print corrupts the JSON-RPC stream and the client fails with parse errors. Log to stderr.

Calling MCP tools synchronously

Adapter tools are async. Use ainvoke and asyncio.run at the top level.

Wrong Python for the server

Use sys.executable so the server runs in the same environment, with mcp installed.

Discussion

Why not just import the Python functions directly?

Within one Python app, you could. MCP pays off when tools are shared across apps and languages, maintained by other teams, or run as separate processes with their own permissions.

Is connecting to an MCP server safe?

Only if you trust it. A server's tool descriptions go into your model's prompt, and its tools run with whatever access the server has. Lecture 034 covers trust and least privilege.
